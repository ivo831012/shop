# Каса и склад

Приложение за продажби и склад за магазин и заведение. Работи на компютър, таблет и телефон, инсталира се като приложение и продава и без интернет.

## Как работи

- Приложението е на **GitHub Pages**: https://ivo831012.github.io/shop/
- Всяко устройство има **собствена база** (SQLite в браузъра) и работи напълно без интернет.
- Основната база е **частно хранилище в GitHub** (например `shop-data`). Когато има връзка, всяко устройство на всеки 20 секунди качва своите промени и изтегля промените на другите.
- Всяко устройство пише само в свои файлове (`ops/<устройство>/<ден>.json`), затова няма конфликти. Всички устройства прилагат едни и същи операции в един и същ ред и стигат до еднакви наличности и отчети.

## Свързване на устройство

1. Отворете https://ivo831012.github.io/shop/ на устройството.
2. Изберете **Свържи с GitHub**.
3. Въведете хранилището с данните (напр. `ivo831012/shop-data`) и ключ за достъп:
   - отворете https://github.com/settings/personal-access-tokens/new;
   - **Repository access:** Only select repositories → хранилището с данните;
   - **Permissions → Contents:** Read and write;
   - **Generate token** и копирайте ключа.
4. На първото устройство създайте администратора. Останалите устройства изтеглят всичко сами.

За да се инсталира като приложение: в браузъра на телефона изберете „Добавяне към началния екран“ (Android: менюто ⋮, iPhone: бутона за споделяне).

Без GitHub: **Пробвай с примерни данни** работи само на устройството, с вход ПИН `0000`.

## Какво може

- **Каса:** бутони по категории, баркод скенер, търсене, плащане в брой (с ресто) или с карта.
- **Заведение:** маси по зони, отворени сметки, които се виждат от всички устройства, „За вкъщи“ и „Доставка“.
- **Артикули:** стоки, рецепти, комбо менюта и услуги. Снимка, баркод, мярка, цена, ДДС група, минимална наличност.
- **Рецепти и менюта:** продажбата изписва съставките от склада. Себестойността и надценката се смятат сами.
- **Склад:** доставки (със средно претеглена доставна цена), брак, ревизия и предупреждения за ниска наличност.
- **Отчети:** оборот за деня, в брой и с карта, по часове, най-продавани, по служители, ДДС по групи, сторно.
- **Потребители:** вход с ПИН код и роли (администратор, управител, касиер, склад).

Предстои: фискален принтер Елтрейд и банков ПОС терминал.

## Сигурност

- Хранилището с данните трябва да е **частно**.
- ПИН кодовете се пазят само като хеш (PBKDF2), никога в явен вид.
- Ключът за достъп стои на устройството. При загубено устройство изтрийте ключа му от https://github.com/settings/personal-access-tokens. Другите устройства продължават да работят.

## Вариант със собствен сървър

Същото приложение може да работи и със сървър (Node.js 22.13+), например за много каси или няколко обекта. Логиката е една и съща (`core/`).

```bash
npm install
npm run build:server
npm run seed     # по желание: примерни данни
npm start        # http://localhost:3000
```

На Windows: двойно щракване на `start-windows.bat`.

## Структура

```
core/     обща логика: схема, склад, рецепти, отчети, дневник на операциите, синхронизация с GitHub
  test/   тестове (npm test)
server/   вариант със сървър (Fastify + node:sqlite)
web/      интерфейс (React + Vite)
.github/workflows/pages.yml   публикуване в GitHub Pages при всяка промяна
```
